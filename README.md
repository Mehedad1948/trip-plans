# برنامه سفر «از کویر تا مه»

یک راهنمای تک‌صفحه‌ای، فارسی و واکنش‌گرا برای سفر پنج‌روزه کاشان تا شمال‌غرب
ایران. برنامه روزها، جاذبه‌ها، پیشنهادهای غذایی، وسایل هر هم‌سفر، گفتگوی گروهی،
هزینه‌ها و نکات ایمنی از یک پایگاه داده محلی SQLite خوانده می‌شوند.

## پیش‌نیاز

- Node.js 22.5 یا جدیدتر (پروژه از ماژول داخلی `node:sqlite` استفاده می‌کند)
- npm

## نصب و اجرا

```bash
npm install
npm run seed
npm run dev
```

سپس `http://localhost:3000` را باز کنید.

صفحه اصلی به سفر فعلی هدایت می‌شود:

```text
/trip/az-kavir-ta-meh
```

## حساب‌های اولیه

پس از اجرای seed، سه حساب زیر آماده‌اند:

| نام کاربری | نام نمایشی | رمز موقت |
| --- | --- | --- |
| `mehrdad` | Mehrdad | `123456` |
| `amir-mohammad` | Amir Mohammad | `123456` |
| `ali` | Ali | `123456` |

رمزها در SQLite به‌صورت hash شده با `scrypt` ذخیره می‌شوند. نشست ورود نیز با
یک token تصادفی، رکورد قابل ابطال در SQLite و cookie امن `HttpOnly` مدیریت
می‌شود. رمز موقت را برای استفاده‌ای فراتر از محیط محلی تغییر دهید.

## پایگاه داده

داده منبع در [`data/trip.json`](data/trip.json) قرار دارد. دستور `npm run seed`:

1. فایل `data/trip.db` را در صورت نیاز ایجاد می‌کند؛
2. جدول‌ها و ارتباط‌ها را می‌سازد؛
3. داده قبلی را در یک تراکنش پاک می‌کند؛
4. کاربران و رمزهای اولیه، عضویت سفر، روزها، فعالیت‌ها، مکان‌ها، تصاویر،
   غذاها، مسئولیت وسایل و نکات ایمنی را وارد می‌کند.

فایل پایگاه داده تولیدی در Git نادیده گرفته می‌شود. بعد از هر تغییر در JSON،
دستور seed را دوباره اجرا کنید.

## دستورها

```bash
npm run dev     # محیط توسعه
npm run seed    # ساخت یا بازنشانی SQLite
npm run lint    # بررسی ESLint
npm run build   # ساخت production
npm start       # اجرای خروجی production
```

کوکی نشست در build پروداکشن به‌صورت پیش‌فرض `Secure` است. فقط برای تست
`npm start` روی HTTP محلی می‌توانید متغیر `SESSION_COOKIE_SECURE=false` را
تنظیم کنید؛ در استقرار HTTPS آن را غیرفعال نکنید.

## معماری

- Next.js 16 App Router و React Server Components
- Tailwind CSS 4
- SQLite داخلی Node.js؛ بدون سرویس یا حساب خارجی
- مسیر مستقل و قابل توسعه برای هر سفر با الگوی `/trip/[slug]`
- کاربران مستقل و عضویت چندبه‌چند در سفرها (`users` و `trip_members`)
- احراز هویت نام کاربری/رمز عبور و نشست‌های قابل ابطال در جدول `sessions`
- وسایل قابل ویرایش با مسئول و وضعیت آماده‌سازی برای هر عضو
- چت overlay در همان صفحه سفر با state تایپ‌شده `?panel=chat` توسط `nuqs`
- دکمه شناور گفتگو در همه اندازه‌ها و نوار ناوبری پایین در موبایل
- هزینه‌ها با ثبت‌کننده مستقل از پرداخت‌کننده، شرکای هزینه، سهم دقیق و پیشنهاد
  تسویه
- یک Client Component کوچک برای وضعیت دکمه‌های فرم و یک wrapper برای fallback تصاویر
- لینک مستقیم Google Maps؛ بدون API key

تمام mutationها هویت را مستقیماً از نشست سمت سرور می‌خوانند و عضویت فرد، سفر
و رکورد هدف را بررسی می‌کنند؛ شناسه کاربر از ورودی فرم پذیرفته نمی‌شود. هر
کاربر می‌تواند یک هزینه را به نام پرداخت‌کننده دیگری ثبت کند و نام ثبت‌کننده
برای حسابرسی نگه داشته می‌شود.

برای ساخت production باید `npm run seed` پیش از `npm run build` اجرا شده باشد.
